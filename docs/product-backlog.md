# Product backlog

This is a prioritized working backlog for the Smart Content Delivery System. Items are written as
outcomes with checkable acceptance criteria. Status reflects the code and documentation currently
in this checkout; re-check it when implementation changes.

## Done

### CDN-01 — Route VIP requests to an available content server

**Outcome:** A client can request content through the virtual IP without knowing the selected
server.

- [x] Controller answers ARP for the VIP and rewrites request and response flows.
- [x] Client can download content and verify its SHA-256 checksum.
- [x] Setup and run steps are documented in the README.

### CDN-02 — Recover downloads after server failure

**Outcome:** A transfer can resume from another healthy server after its selected server fails.

- [x] Heartbeats mark a server down after the configured timeout.
- [x] Flows to the failed server are removed so reconnection reaches the controller.
- [x] The client resumes by byte offset and the failover check validates the checksum.

### CDN-03 — Compare static and dynamic server selection

**Outcome:** The project can run repeatable experiments and summarize results for both modes.

- [x] Experiment runner supports normal, congested, and failed-server conditions.
- [x] CSV results, graphs, and a summary are generated by the documented scripts.
- [x] Documentation identifies that existing measurements predate the six-client topology and
  need to be rerun before they are treated as final.

## Prioritized next work

### CDN-04 — Reproduce the experiment results on the current topology

**Priority:** High

**Outcome:** Results correspond to the six distinct experiment clients and current controller
behavior.

- [ ] Run all three conditions in both static and dynamic modes using the current topology.
- [ ] Record run configuration and repetition count with the output data.
- [ ] Regenerate the CSV, graphs, and summary from those runs.
- [ ] Document any failed or excluded run and why; do not silently replace measurements.

### CDN-05 — Make experiment runs reproducible

**Priority:** High

**Outcome:** Another developer can reproduce a run from a recorded seed and configuration.

- [ ] Randomized conditions accept and record an explicit seed.
- [ ] Output identifies mode, condition, client count, file, and run identifier.
- [ ] Repeating a run with the same seed reproduces the generated workload.
- [ ] README explains how to select the seed and locate the run metadata.

### CDN-06 — Verify setup from a clean checkout

**Priority:** Medium

**Outcome:** Installation and demo instructions work without relying on local files or shell state.

- [ ] Follow the documented setup in a clean Ubuntu VM or record exact blockers.
- [ ] Confirm scripts have the required executable permissions and dependencies are listed.
- [ ] Run the checksum and failover demos and capture their observed result.
- [ ] Update setup instructions to match the verified environment.

### CDN-07 — Consolidate experimental helper scripts

**Priority:** Medium

**Outcome:** Experimental changes are understandable and do not leave ambiguous competing entry
points at the repository root.

- [ ] Decide which helper scripts are supported, archival, or obsolete.
- [ ] Move supported utilities under an appropriate directory and document their purpose.
- [ ] Remove obsolete copies only after confirming their changes are represented elsewhere.
- [ ] README lists the supported commands and their expected use.

## Backlog maintenance

When an item is completed, check off its criteria and move it to Done with a short evidence note
(command, output file, or demo). Split items that prove too large for one iteration. Add newly
discovered work with an ID, priority, outcome, and acceptance criteria.
